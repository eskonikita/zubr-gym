# Анализ и план ZUBR GYM

## 1. Объём и источники

Текущая задача — принять материалы, извлечь картинки, определить типы страниц, дизайн-систему и последовательность работы. Разработку выполняем далее постранично. 25 URL Bronx не означают 25 отдельных макетов или обязательство перенести все разделы.

КП описывает коммерческий объём, а приложенный общий текст — более широкие пожелания к качеству и реализации. Вложенный текст не запускает работу сам по себе. Текущий запрос пользователя задаёт границу этого этапа.

В КП указано:

- Стоимость разработки — 700 BYN. Домен и хостинг оплачиваются отдельно.
- Дизайн и согласование, адаптивная вёрстка, сборка страниц и меню, тестирование.
- MODX Revolution с редактированием направлений, тренеров, цен, расписания и контента.
- Базовая аналитика, включая клики по телефону; SEO/GEO-подготовка и запуск при наличии доступов.
- Семь основных разделов: главная, о зале, направления, расписание, тренеры, цены, контакты.
- Основное действие — звонок. «Бесплатная тренировка» используется, если предложение подтверждено.
- Формы заявок, онлайн-запись, онлайн-оплата, CRM, ежемесячное SEO и регулярное ведение не входят.
- Срок согласуется после утверждения объёма и получения материалов; фиксированной даты в КП нет.
- Макеты предварительные. Утверждения о федерации, акции и фактические тексты требуют подтверждения.

## 2. Расхождения, которые влияют на проект

| Источник | Наблюдение | Рабочее решение |
| --- | --- | --- |
| Общее задание | Просит формы и все страницы референса | Границы текущего этапа и выбор шаблонов определяет прямой запрос пользователя |
| КП | Звонки, без форм и онлайн-записи | Основные CTA ведут на `tel:`, контактные — на контакты/маршрут |
| Bronx | Заявки, Telegram-бот, покупка абонементов, кабинет | Не переносить эти механизмы в базовую реализацию |
| Bronx | Четыре направления и четыре аудитории | Подтверждены только темы макета: тайский бокс и кикбоксинг. Остальное — кандидаты, а не услуги ZUBR по умолчанию |
| КП | Семь главных разделов | В первую очередь проектировать их и один типовой экран направления |
| Старые локальные заметки | Тёплая светлая палитра, Manrope/Inter, другой порядок мобильного hero | Текущая система основана на новых присланных изображениях; старые файлы не переписаны |

Фраза «Получить бесплатную тренировку» не должна открывать форму в базовом объёме: при подтверждённой акции это звонок с доступным пояснением «Позвоните, чтобы договориться о тренировке». Без подтверждения — нейтральное «Позвонить в зал». Не использовать обещание статуса представительства федерации как установленный факт.

## 3. Что есть в выгрузке

В `public/` находится рабочая локальная копия, в `reference/bronxgym/` — оригинал. Это опубликованные HTML и скомпилированные React/TanStack-ресурсы, не исходники компонентов. MODX и база ещё не установлены. Доступны Node-сервер, Playwright и отдельные каталоги будущих элементов MODX.

Правки поверх сохранённого HTML могут перезаписываться React при гидратации. Поэтому будущие образцы верстаем собственными HTML/CSS/JS-компонентами; CSS-токены не следует смешивать со скомпилированными стилями Bronx. Способ хранения новых образцов определим при начале реализации, сохраняя исходную выгрузку.

### Карта всех 25 маршрутов

| Тип | Маршруты Bronx | Как использовать |
| --- | --- | --- |
| Главная | `/` | Один самостоятельный шаблон |
| Обзор раздела | `/directions`, `/for`, `/club`, `/info` | Один шаблон сетки/списка ссылок с вариантами наполнения; базовый образец — направления |
| Направление | `/directions/muay-thai`, `/directions/kickboxing`, `/directions/boxing`, `/directions/free-training` | Один шаблон, первый образец — тайский бокс; другие направления только при наличии в ZUBR |
| Аудитория | `/for/kids`, `/for/women`, `/for/beginners-30-plus`, `/for/amateurs` | Вариант контентного шаблона; отдельные страницы — по согласованной структуре |
| Контентная страница | `/club/gym`, `/club/first-visit` | Один базовый шаблон с секциями фото/текст/шаги/FAQ; первый образец — о зале |
| Тренеры | `/club/coaches` | Один шаблон списка тренеров; отдельного URL профиля в выгрузке нет |
| Галерея | `/club/media` | Дополнительный шаблон при необходимости; сначала фотоблок внутри страницы о зале |
| Расписание | `/info/schedule` | Самостоятельный шаблон данных и фильтров |
| Цены | `/info/prices` | Самостоятельный шаблон тарифов и условий |
| Контакты | `/info/contacts` | Самостоятельный шаблон контактов и маршрута |
| FAQ | `/info/faq` | Дополнительный шаблон FAQ, если объём требует отдельного раздела |
| Текстовый документ | `/info/privacy`, `/info/terms`, `/info/cookies`, `/info/offer` | Один шаблон документа; состав и тексты определяются фактическим функционалом ZUBR |

Итого: 10 основных семейств шаблонов плюс отдельная галерея при необходимости. Аудитория — вариант контентного шаблона. В первой очереди нужны 8 образцов: главная, обзор направлений, направление, о зале, тренеры, расписание, цены, контакты. Документы, FAQ и галерею подключаем по потребности. Прежнюю оферту Bronx не переносить.

Сейчас страницы физически не удаляем: они нужны для сверки структуры. Сокращаем именно будущую работу по вёрстке; повторные ресурсы в CMS будут использовать готовые шаблоны.

Конкретные исходные HTML-файлы для каждого образца и рабочие имена будущих шаблонов зафиксированы в [выборе шаблонов](template-selection.md).

## 4. Состав образцов

### Главная

Выгрузка: hero → зал изнутри → направления → аудитории → первый визит → тренеры → FAQ → блок заявки. Практические данные также доступны через меню и футер.

Предлагаемый ZUBR: hero по двум макетам → фото и краткое описание зала → направления → группы, если подтверждены → первый визит через звонок → тренеры → компактные переходы к расписанию/ценам → FAQ → адрес, телефон и маршрут → футер. Добавление кратких расписания/цен и адреса соответствует КП; не переносить форму заявки. Порядок секций уточняется при разборе главной.

### Обзор направлений

Крошки → H1 и короткий вводный текст → карточки существующих направлений → помощь с выбором через звонок → связанные расписание и цены. Не создавать пустые карточки ради сетки.

### Типовое направление

Крошки → заголовок, краткое описание и фотография → как проходит тренировка → что отрабатывают → связанные тренеры и расписание → кому подходит → FAQ → звонок. На основе одного образца тайского бокса делаем кикбоксинг через данные; свободная тренировка, если нужна, использует вариант секций без обязательного тренера.

### О зале и другие контентные страницы

Крошки → вводный блок → фактические условия и оборудование → фотографии → направления → связанные тренеры/расписание/цены → FAQ → контакты. Страница первого визита использует тот же каркас с шагами «позвонить → согласовать группу → прийти», списком вещей и ответами. Не выдумывать площадь, количество тренеров или достижения.

### Тренеры

Крошки → H1 и вводный текст → повторяемые блоки с портретом, именем, специализацией, опытом, подтверждёнными достижениями → ссылка на подходящие группы → звонок. Без отдельного сложного профиля на каждого тренера.

### Расписание

Крошки → H1 и пояснение → фильтр направления и дня; тренер/возраст/уровень только при достаточном количестве групп → расписание → состояние «по этим условиям групп нет» со сбросом → звонок. В Bronx есть фильтры направлений/аудиторий и тренера; для ZUBR выбираем реально полезные. На мобильном — последовательные карточки занятий, на десктопе — читаемая таблица или список. Дни, время, направление, группа, тренер должны редактироваться в MODX. Состояние пустого результата обязательно, счётчик групп вычисляется из данных.

### Цены

Крошки → H1 → разовое занятие/абонементы → число занятий, срок, цена BYN и условия → пробная тренировка, если подтверждена → звонок. В Bronx есть переключатели взрослый/ребёнок, группа/свободный зал и типов пакетов. Для ZUBR не переносить фильтры без реальной тарифной матрицы. Нет покупки, корзины и оплаты.

### Контакты

Крошки → H1 → телефон, адрес, график работы, социальные сети → карта или ссылка на маршрут → фото входа и инструкция, если доступны → звонок. Форма «Вопрос о тренировках» из референса исключается в рамках КП. Ссылки на соцсети и карты ведут на фактические ресурсы ZUBR.

### Дополнительные типы

FAQ: тематические группы вопросов, раскрытие ответов, телефон. Галерея: фотографии с подписями и просмотром крупно; клавиатура, Escape, возврат фокуса. Документ: H1, дата версии, удобная ширина текста, H2/H3, списки и ссылки. 404 — служебное состояние общего каркаса с возвратом на главную и контактами.

## 5. Общие элементы и MODX

Общие чанки: header, desktop-nav, mobile-nav, footer, breadcrumbs, button-link, section-heading, direction-card, coach-card, schedule-item, price-card, faq-item, contact-block, call-cta. Галерея и фильтры — отдельные небольшие JS-модули. Не создавать общий комбайн, который выводит любую страницу из произвольного JSON.

| Данные | Предложение для будущей CMS |
| --- | --- |
| Телефон, адрес, часы, соцсети, логотип | Общие настройки сайта; один источник для всех страниц |
| Направление | Ресурс: заголовок, slug, meta, вводный текст, фото, секции, связи с тренерами, FAQ |
| Тренер | Ресурс или структурированная запись: имя, портрет, специализация, опыт, достижения, связанные направления |
| Расписание | Повторяемые записи: дни недели, начало/окончание, направление, группа, тренер, порядок, активность |
| Тариф | Повторяемые записи: название, стоимость BYN, число занятий, срок, аудитория при необходимости, условия, порядок |
| FAQ/фото | Повторяемые записи с порядком и привязкой к странице |
| SEO | Title, description, единственный H1, canonical, OG, внутренние ссылки |

TV и конкретные дополнения MODX выберем при интеграции. Важнее сейчас не зашить расписание и цены в JS и сделать чистую повторяемую разметку. Метаданные и разметка сущностей используют только подтверждённые данные; SEO/GEO не означает гарантии трафика или ответов ИИ.

## 6. Порядок постраничной работы

1. **Главная и каркас.** Уточнить состав её секций, подготовить отдельные графические исходники, подключить шрифты/токены, сделать header/footer и оба варианта hero. Проверить 320–430, 768, 1024 и 1440 px. Согласовать визуальный язык на этой странице.
2. **Обзор направлений и одно направление.** Взять тайский бокс как подробный образец. Проверить длинные кириллические заголовки, изображения, FAQ и связанные группы. Второе направление не перевёрстывать.
3. **О зале.** Отработать базовую контентную страницу, фотоблок и варианты секций. Первый визит и аудитории — последующее наполнение того же каркаса, если нужны.
4. **Тренеры.** Один шаблон с повторяемыми блоками; проверить разные длины имени и описания.
5. **Расписание.** Сначала модель реальных данных, затем фильтры и обе компоновки. Проверить несколько дней, отсутствующего тренера, длинную группу и пустой результат.
6. **Цены.** Сначала реальные тарифы и условия, затем карточки/таблица. Переключатели только при необходимости.
7. **Контакты.** Фактические реквизиты, маршрут, фото входа, действия телефона и соцсетей.
8. **Дополнительные шаблоны и состояния.** Текстовый документ, FAQ/галерея при необходимости, 404. Финальная сверка общей системы.
9. **MODX и запуск.** Перенести согласованную вёрстку в шаблоны/чанки, подключить редактирование данных, аналитику и метаданные, проверить ссылки и адаптивность. Перед публикацией убрать локальные ограничения только на готовом продакшене.

На каждом этапе: завершённая страница на тестовом содержимом, адаптивная проверка и работоспособность её элементов. Затем переход к следующему типу по запросу пользователя. Сейчас эти шаги не выполняются автоматически.

## 7. Материалы до финального наполнения

Нужны отдельные исходники логотипа и маскота, реальные фото зала/входа/тренеров, телефон, адрес, график, соцсети, направления, группы, расписание, тарифы, данные команды. Отдельно подтвердить бесплатную тренировку и формулировку о федерации. Доступы к хостингу, домену и аналитике нужны на этапе интеграции/запуска, не для нынешнего анализа.

Черновые блоки можно готовить заранее с явно отмеченными полями, но факты Bronx и прежние неподтверждённые заметки не выдавать за данные ZUBR.

## 8. Критерии приёмки будущих шаблонов

Одна система компонентов и токенов; живые тексты и кнопки; кириллица без подмены гарнитуры; нет горизонтального переполнения на 320–430 px; телефон и маршрут действуют; меню/FAQ/фильтры работают с клавиатуры; видимый focus; корректные пустые состояния; цены и расписание пригодны для вывода из CMS. Hero не перекрывает содержание и не требует фиксированной высоты экрана. Фото оптимизированы, hero загружается сразу, фотографии ниже — лениво. Нет чужих реквизитов, формы заявки и оплаты вне согласованного объёма.
