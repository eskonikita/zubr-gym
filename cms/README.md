# ZUBR GYM — MODX

Актуальный контекст: `docs/zubr/CONTEXT.md`. Локальный сайт: http://zubr-gym.local/ ; админка: http://zubr-gym.local/manager/ .

Подготовлен перенос на **https://zubr-gym.by/**: [DEPLOY.md](../DEPLOY.md). Код ядра MODX и установленных пакетов теперь включён в Git. Секретные конфиги, кеш/логи, установочные архивы пакетов и SQL исключены; готовый приватный архив файлов и продовый дамп находятся в `artifacts/`. На сервере сохраняйте структуру проекта и направляйте DocumentRoot на `public/`, затем выполните `tools/deploy/configure.php` по инструкции.

## Окружение и доступ

MODX Revolution **3.2.4-pl**, Open Server Panel, PHP 8.3, MySQL 8.2, web root `public/`. Пакеты: **Ace 1.9.8-pl**, **pdoTools 3.0.3-pl2**, **MIGX 3.0.2-beta1**, **ClientConfig 2.5.0-pl**. MIGX — официальный совместимый с MODX 3 beta-пакет; исправления строгого MySQL 8 воспроизводятся через `tools/modx/migx-compat.php`.

Логин `admin`. Пароль, параметры отдельной базы `zubr_gym_local` и приватное состояние браузера — только в игнорируемом `cms/private/`. Резервные копии в `cms/backups/` тоже исключены из Git. Не публикуйте эти файлы. Установщик удалён, служебные каталоги и конфигурации закрыты Apache.

## Шаблоны, чанки и поля

**20 шаблонов по типам, 32 ресурса, 30 отображаемых HTML-страниц.** Удалены префикс ZUBR, категория ZUBR GYM · HTML, неиспользуемый BaseTemplate и дубли объединённых шаблонов.

Общие типы:

- «Направление» (14): кикбоксинг и тайский бокс.
- «Аудитория» (16): четыре страницы «Для кого».
- «Статья блога» (25): три материала.
- «Документ» (8): политика и соглашение.
- «Тренер — одиночная» (13): профиль тренера; «Тренеры — список» (10): список.
- Остальные страницы имеют названия своего типа: Главная, Контакты, Цены, Расписание, Галерея и т. д.

Чанки в категории **Общие**: `head`, `header`, `footer`, `mobileMenu`, `svgSprite`, `breadcrumbs`, `trainingCta`, `relatedArticles`, `articleCard`, `coachQualification`, `galleryDialog`. Все имена чанков английские.

Каждый шаблон начинается с `[[$head]]`. Этот чанк содержит doctype, html, общую секцию head и открытие body. Общие стили, favicon и метаданные подключаются здесь один раз. Сниппет `PageHead` (код `cms/elements/PageHead.php`) выбирает дополнительные стили/скрипты, preload, CSP для карты и CSS-классы body по типу страницы. Порядок подключений сохранён. Кнопка scroll-to-top находится в `footer`; в шаблонах её не дублируем.

В ресурсе **Дополнительные поля (TV)**:

- «Содержимое страницы»: заголовок H1, описание, текст приглашения. Заголовок поддерживает span для красного акцента.
- «Направление» / «Аудитория»: индивидуальные тексты и изображения общих шаблонов.
- «Тренер»: фото, специализация, стаж, описание, квалификация в MIGX.
- «Статья»: категория, изображение, alt, выбор связанных статей.
- «SEO»: метаданные и индексация.

Основные тексты статей и юридических документов, подробные секции тренера — в обычном поле **Содержимое**. Оглавление статей и документов строится из заголовков секций. Повторяемые блоки оставшихся страниц пока ещё находятся в шаблонах; последующее выделение в MIGX выполняется отдельным этапом.

Профили 14–17 находятся под ресурсом 10. URL — `/club/coaches/имя/`, со старых `/coaches/имя/` настроены 301. HTML content type использует суффикс `/`.

## ClientConfig

Открыть: **Пакеты → ClientConfig** либо `/manager/?a=home&namespace=clientconfig`. Настроено 21 поле в трёх вкладках:

1. Контакты: телефон, email, Instagram, адрес зала, домен в контактных подписях.
2. Карта и время работы: ссылки на карту/маршрут/iframe и часы по дням.
3. Реквизиты организации: названия, УНП, юридический адрес, директор, банковские данные.

Примеры обращения: `[[++zubr_contact_phone:htmlent]]`, `tel:[[++zubr_contact_phone:ZubrPhone]]`, `[[++zubr_contact_email:htmlent]]`. Телефон задаётся один раз, ссылка для звонка формируется из него. Instagram — имя без @; из него строятся адрес и подпись. Короткий адрес получается модификатором ZubrStreet. Значения экранируются при выводе в HTML.

Сохранение ClientConfig автоматически очищает кеш всех страниц через плагин «Обновление общих контактов». Проверено изменение через админку с распространением на все 27 страниц, включая метаданные. Исходное наполнение и воспроизводимая настройка — `cms/contact-settings.json`, `tools/modx/configure-contacts.php`; повторная настройка сохраняет существующие значения.

## SEO и индексация

Единый `[[!ZubrSeoHead]]` выводит title/description, OG и Twitter Card из SEO TV. Изображение по умолчанию: `/zubr/images/social-share.jpg` (1200×630), настройка `zubr_seo_default_image`. SEO поля поддерживают ссылки на общие контакты; код расширяет только разрешённые контактные настройки.

Canonical строится из URI ресурса; UTM удаляются, действительная пагинация блога сохраняет `?page=N` и добавляет номер в метаданные. 404/503 не имеют canonical и возвращают соответствующие HTTP-коды.

**Индексация на локальном сайте включена по прямому запросу владельца.** `zubr_indexing_enabled=1`. Галочка seo_index задаёт index/follow или noindex/nofollow и исключение из sitemap. Ошибки и служебные ресурсы исключены; опубликованные 29.10.2026 политика и соглашение индексируются. robots.txt и sitemap.xml — динамические ресурсы 39/40; карта строится через pdoSitemap. MODX даты обрабатываются как datetime или timestamp, без преобразования года в секунды эпохи.

Friendly URLs и транслитерация русских алиасов включены. В `.htaccess` подготовлены www/HTTP → `https://zubr-gym.by`; production SSL и перенос на хостинг ещё не выполнялись. При прокси/CDN требуется согласовать определение HTTPS. Локальный HTTP сохраняется.

## Иконки

Прозрачная красная боксёрская перчатка: SVG, ICO 16/32/48, PNG 16/32/48/180/192/512, Apple Touch Icon и site.webmanifest. Для обхода старого браузерного кеша активные ссылки используют имена boxing-glove. Прозрачные иконки не объявляются maskable. Манифест сам по себе не добавляет офлайн-режим.

Перегенерация: `node tools/modx/build-icons.mjs`, затем `php tools/modx/configure-icons.php --apply`. Общая разметка — в чанке `head`, обновление иконок выполняет `cms/elements/Icons.php`; configure-icons обновляет и общий head.

## Исходники и перенос

Рабочие данные — в базе MODX. `cms/template-registry.json` фиксирует текущие типы и ID; `cms/import-result.json` — ресурсы. Экспорт исходников элементов для просмотра и Git:

```powershell
& 'C:/OSPanel/modules/PHP-8.3/PHP/php.exe' tools/modx/export-elements.php
```

Он обновляет `cms/templates/structured/<ID>.html`, `cms/chunks/*.html`, `cms/tv-definitions.json` и ничего не импортирует обратно в CMS. Перед миграциями сохраняются снимки. Старый whole-HTML импорт `tools/modx/import-static.php` теперь блокируется, чтобы не уничтожить TV, чанки и тексты ресурсов.

`public/**/*.html` остаётся отдельным статическим предпросмотром с буквальными значениями. PHP/MODX и секреты не попадают в Pages. Изменения базы требуют переноса SQL вместе с CMS, одного Git недостаточно.

Проверки:

```powershell
node tools/modx/verify-seo.mjs
node tools/build-pages.mjs
node tools/check-links.mjs dist /zubr-gym/
```

`npm run dev` запускает только статический сервер. Для текущего MODX используйте Open Server Panel.

Модальное окно фотографий — чанк `galleryDialog`. Подключено только на главной (шаблон 2) и в галерее (12), где есть кнопки `data-gallery`. На остальных страницах окно не выводится; общий home.js корректно работает без него. Новая страница с просмотром фото должна явно подключать этот чанк.

Общий каркас: `[[$head]]` открывает документ, `header` содержит skip-link перед шапкой, `footer` выводит кнопку вверх, mobileMenu и закрывает body/html. Последний вызов каждого шаблона — `[[$footer]]`. На главной и в галерее `[[$galleryDialog]]` идёт перед footer. Не добавляйте разметку после footer.

В конце чанка `head`, после открытия `<body>`, уже подключён `[[$svgSprite]]`. В шаблонах отдельно его не вызывайте: начало страницы — `[[$head]]`, затем `[[$header]]`.
